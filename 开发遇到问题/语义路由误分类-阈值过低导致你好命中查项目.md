# 语义路由误分类：发送「你好」被当成「查项目」

> 记录时间：2026-08-18 ｜ 模块：后端 / 语义路由（intent_router） ｜ 状态：已修复

## 问题描述（现象）

用户在图谱咨询助手对话框发送一句普通问候「你好」，模型的回复却是查项目的结果——「你共有 1 个知识图谱项目：…」。即：**语义路由把「你好」误分类成了 `query_project` 意图**，走了查库专项处理，而没有走正常的 LLM 聊天。

## 影响

- 固定意图分流（省 token、秒回）被误触发，用户随口一句问候也会被扣成一次查项目。
- 若误分类为 `build_graph`，还会白调一次 LLM 提取。
- 属于意图识别质量的**误命中**问题，会直接污染用户体验。

## 根因分析

### 直接原因：命中阈值过低

semantic-router 库的 `LiteLLMEncoder` **默认 `score_threshold = 0.3`**（cosine 相似度）。它的判定逻辑是：`相似度 ≥ 阈值` 就命中该意图。而实测「你好」对三条意图的相似度为：

| 意图 | 最高相似度 | ≥ 0.3？ |
|---|---|---|
| query_project | **0.3417** | ✅ 误命中 |
| chat | 0.2806 | 否 |
| build_graph | 0.2650 | 否 |

「你好」这类**中文短句在语义空间里与任意句子普遍有 0.3+ 的相似度**，于是被「够得着」的 `query_project` 抢走。

### 深层原因

- semantic-router 0.1.2 把默认阈值定在 0.3，**没有针对业务场景校准**，直接用等于裸奔。
- 嵌入模型 `Qwen3-VL-Embedding-8B`（8B 多模态模型）对短文本的区分度一般，也放大了低阈值的问题（详见「后续建议」）。

## 排查过程

1. 用户在真实操作中触发 → 日志显示 `query_project` 分支被命中。
2. 写脚本直接调 `_build_router()`，用真实 embedding 打印「你好」对所有 utterances 的相似度得分：
   - `score_threshold = 0.3` 浮出水面（库里默认值）。
   - 「你好」对 query_project 的 max score = **0.3417**，越过 0.3。
3. 对照组确认区分度没问题：
   - 「我有哪些项目」0.77~0.99、「帮我建个图谱」0.86~0.95、「RDF和属性图有什么区别」0.68~0.99（全部远高于 0.34）。
   - 结论：不是 embedding 失效，就是**阈值定低了**。

## 解决方案

把命中阈值从 0.3 上调到 **0.5**，并做成可配置项：

1. `backend/app/core/config.py` 新增配置：
   ```python
   embedding_score_threshold: float = 0.5
   ```
2. `backend/app/services/intent_router.py` 传给 encoder：
   ```python
   encoder = LiteLLMEncoder(
       name=f"hosted_vllm/{settings.embedding_model}",
       api_key=settings.embedding_api_key,
       score_threshold=settings.embedding_score_threshold,
   )
   ```
3. `backend/.env.example` 补示例：`EMBEDDING_SCORE_THRESHOLD=0.5`

阈值 0.5 的选取依据（实测）：

| 输入 | 旧阈值 0.3 | 新阈值 0.5 |
|---|---|---|
| 你好 | ❌ query_project | ✅ None |
| 随便聊聊 / 今天天气不错 | — | ✅ None |
| 我有哪些项目 | ✅ query_project | ✅ query_project |
| 帮我建个图谱 | ✅ build_graph | ✅ build_graph |
| RDF和属性图有什么区别 | ✅ chat | ✅ chat |

真意图句得分全在 0.68+，无关短句 ≤ 0.41，0.5 正好卡在中间，既滤误报又不误杀。

## 验证结果

- 修改后脚本实测 8 条查询：「你好/随便聊聊/今天天气不错」→ None，「我有哪些项目」等 5 条真意图 → 各自正确命中。
- 后端重启后 `/docs` 200、前端 `/` 200，服务正常。
- ⚠️ 注意：`_build_router()` 是 `lru_cache` 缓存，**改代码后必须重启后端进程**才生效。

## 经验教训 / 预防

1. **第三方库的默认阈值≠生产阈值**：semantic-router 的 0.3 面向通用场景，接入业务必须用真实语料校准，不能直接用默认值。
2. **语义路由对"无关输入"要有明确测试**：应加一类"非意图闲聊句（你好/随便聊聊）必须返回 None"的回归用例，防止阈值漂移。
3. **相关待办**：
   - `Qwen3-VL-Embedding-8B` 是多模态 8B 模型，文本语义路由偏重且区分度一般，建议换 `BAAI/bge-m3`（中文友好、更准更快）。
   - 可对每条意图分别配置阈值（`route.score_threshold`），替代现在的全局阈值。
   - 建议补充更多 utterances 样本并用评估集（含负例）回归，见功能清单「路由效果调优」待办。
