# 删 chat 意图后图谱咨询句误入 build_graph

> 记录时间：2026-08-18 ｜ 模块：后端 / 语义路由（intent_router） ｜ 状态：已修复

## 问题描述（现象）

因 `chat` 意图命中后与 `None` 行为完全一致（都走 LLM 聊天），认为它是"白设的意图"，将其从 `ROUTES_DATA` 中删除。删除后，原来被 `chat` 吸附的图谱咨询类短句（如「RDF和属性图有什么区别」「知识图谱可视化有什么建议」）找不到最匹配的意图，在剩余意图中选了相似度最高的 `build_graph`，导致回复变成「请把你想要建模的内容直接发给我」——体验很差。

## 影响

- 图谱咨询类短句（不含素材的关键词句）被误分类为 `build_graph`，返回引导语或错误的 LLM 提取。
- 用户正常提问（如"RDF和属性图有什么区别"）得不到预期回答。

## 根因分析

1. **直接原因**：`chat` 意图删除后，图谱相关短句在剩余 3 个意图（`query_project` / `build_graph` / `greeting`）中找不到语义匹配，但 `build_graph` 的 utterances 也涉及图谱领域（"帮我建个图谱"等），在 8B 多模态 embedding 模型下图谱相关短句之间普遍有 0.5+ 的相似度，越过了阈值。
2. **深层原因**：`chat` 意图虽然命中后没有专项处理（行为与 `None` 一致），但它的存在价值不是"有处理"，而是**作为"吸附路由"阻止图谱咨询类短句被 `build_graph` 误吃**。意图路由中的"无处理"意图可能是必要的语义锚点，不能因为"没处理"就删。

## 实测数据（删 chat 后的真实分类）

| 输入 | 实际命中 | 期望 |
|---|---|---|
| RDF和属性图有什么区别 | **build_graph** ❌ | chat / None |
| 知识图谱可视化有什么建议 | **build_graph** ❌ | chat / None |
| 你好 / 嗨 / 你是谁 | greeting ✅ | greeting |
| 我有哪些项目 | query_project ✅ | query_project |
| 帮我建个图谱 | build_graph ✅ | build_graph |

## 解决方案

**保留 `chat` 意图**，作为"占位路由"——它的 utterances 吸附图谱咨询类短句，命中后不做专项处理，自然落到 `None` 一样的 LLM 兜底路径。`prepare_chat` 不需要加 `chat` 分支，代码不增加。

修改：
- `intent_router.py`：`ROUTES_DATA` 加回 `chat` 意图的 utterances（与原版一致）。
- 注释说明：`chat` 为占位路由，防误入 `build_graph`。

验证（改回后实测）：

| 输入 | 命中 |
|---|---|
| RDF和属性图有什么区别 | chat ✅ |
| 知识图谱可视化有什么建议 | chat ✅ |
| 你好 / 你是谁 | greeting ✅ |
| 我有哪些项目 | query_project ✅ |
| 帮我建个图谱 | build_graph ✅ |
| 随便聊聊 | None ✅ |

## 经验教训

1. **意图路由里的"无处理"意图可能是必要的**：它不处理任何事，但作为语义锚点阻止其他意图误命中。删意图前必须实测删除后的分类变化，不能只看"处理分支有没有"。
2. **意图设计不是 or 问题**：`chat` 是否需要处理 ≠ `chat` 是否需要存在。一个是业务决策，一个是路由准确性。
3. **8B 多模态 embedding 模型对长尾/短文本区分度差**：图谱领域的短句之间相似度偏高，更容易误命中。换 `bge-m3` 可缓解，但即便换了模型，占位意图的语义锚点作用仍然有价值。
4. **建议后续给 `chat` 加实际处理**：比如命中高置信度咨询时切换更专业的系统提示词，或引导用户指定咨询方向，让这个"占位"变成真正的价值——但前提是不影响其吸附作用。
